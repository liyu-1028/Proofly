# 审稿宝前端全局样式规范

本文档用于指导审稿宝 Vue 3 前端的页面设计和样式实现。目标不是制作品牌手册，而是给后续开发提供统一、可落地的界面规则。

审稿宝面向广告制作店、图文打印店、快印店、包装印刷店和设计工作室。前端应优先服务高频工作流：创建项目、上传设计稿、查看客户标注、上传新版本、客户确认定稿和确认留痕。

前端组件库固定使用 Element Plus，并配套使用 `@element-plus/icons-vue`。后台表单、表格、弹窗、分页、上传、消息提示、标签等基础组件优先使用 Element Plus；审稿预览、标注画布等业务强定制区域可在 Element Plus 布局和反馈组件基础上自定义实现。

## 设计定位

### 总体风格

- 清晰、克制、易扫描。
- 后台页面偏工作台和业务系统，不做营销型首页。
- 页面要突出项目状态、版本状态、标注状态和确认状态。
- 视觉层级依靠排版、间距、边框和状态色建立，不依赖夸张阴影、渐变和装饰图形。
- 保持信息密度适中，适合门店老板和设计师反复查看、筛选、处理。

### 使用场景差异

| 场景 | 主要使用者 | 样式重点 |
| --- | --- | --- |
| 门店后台 | 门店老板、设计师、管理员 | 数据管理、列表筛选、状态流转、批量查看 |
| 客户审稿页 | 客户 | 设计稿预览、标注修改意见、提交反馈、确认定稿 |

后台页面可以承载更高信息密度；客户审稿页应减少干扰，让客户一进入页面就能看图、标注、提交或确认。

## 色系规范

当前前端基线采用“深蓝 + 青绿 + 中性灰”。后续页面应沿用这个方向，避免每个模块重新定义一套颜色。

### 品牌与结构色

| 用途 | 颜色 | 说明 |
| --- | --- | --- |
| 后台导航深蓝 | `#14213d` | 侧边栏、主导航背景 |
| 导航激活深蓝 | `#213356` | 导航 hover、选中状态 |
| 主操作青绿 | `#2a9d8f` | 主按钮、确认动作、品牌标记 |
| 主操作深青 | `#14796d` | 主按钮 hover、成功标签文字 |
| 页面背景 | `#f5f7f8` | 后台主内容背景 |
| 内容背景 | `#ffffff` | 面板、表格、表单区域 |

### 文本色

| 用途 | 颜色 | 说明 |
| --- | --- | --- |
| 主文本 | `#182026` | 标题、重要字段、正文 |
| 次级文本 | `#5d6b78` | 描述、说明、辅助信息 |
| 弱文本 | `#64727f` | 表格辅助列、指标说明 |
| 深色背景文本 | `#f8fafc` | 深蓝导航上的主文本 |
| 深色背景次级文本 | `#b7c4d4` | 深蓝导航上的辅助文本 |

### 边框与分隔

| 用途 | 颜色 | 说明 |
| --- | --- | --- |
| 标准边框 | `#dde4ea` | 面板、表格、输入框边框 |
| 弱边框 | `#e2e8ef` | 列表项、分隔线 |
| 浅色填充 | `#f8fafc` | 表头、禁用区、轻量背景 |

### 状态色

| 状态 | 背景色 | 文本色 | 使用场景 |
| --- | --- | --- | --- |
| 成功 / 已确认 | `#e8f6f3` | `#14796d` | 确认定稿、处理完成 |
| 信息 / 待反馈 | `#eaf2ff` | `#2563eb` | 等待客户反馈、普通提示 |
| 警告 / 待确认 | `#fff7e6` | `#b7791f` | 等待确认、链接即将过期 |
| 错误 / 失败 | `#fdecec` | `#c2413a` | 上传失败、链接失效、校验错误 |
| 中性 / 已归档 | `#eef2f5` | `#52616f` | 已归档、已停用 |

状态色只能用于表达业务状态或操作反馈，不作为大面积背景装饰。

## 页面布局

### 后台布局

- 默认使用左侧导航 + 右侧内容区。
- 侧边栏宽度建议 `248px`，背景使用 `#14213d`。
- 主内容区背景使用 `#f5f7f8`，页面内通过白色面板承载数据。
- 主内容区桌面端 padding 建议 `28px`，移动端降为 `20px`。
- 页面顶部使用标题 + 辅助说明 + 右侧主要操作按钮的结构。

后台页面推荐结构：

```text
page
├── page-header
│   ├── title + subtitle
│   └── primary action
├── filters / summary metrics
└── content panel / table / list
```

### 客户审稿页布局

- 客户页应弱化后台导航，不显示复杂管理入口。
- 首屏突出项目名称、当前版本、设计稿预览和主要操作。
- 标注工具靠近预览区域，提交反馈和确认定稿按钮要清晰可见。
- 移动端优先保证查看设计稿、添加标注、填写意见和确认定稿四个动作可完成。
- 设计稿预览区应使用稳定尺寸和明确边界，避免图片加载后造成页面大幅跳动。

### 卡片和面板

- 卡片只用于独立信息块、列表项、弹窗和工具面板。
- 页面区块不要层层套卡片。
- 面板默认白底、`1px` 边框、`8px` 圆角。
- 阴影只在弹窗、浮层、下拉菜单中使用，普通列表和面板优先使用边框。

## 字体与排版

### 字体

默认字体栈：

```css
Inter, ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif
```

中文内容直接使用系统默认中文字体渲染，不单独引入大型字体文件。

### 字号层级

| 场景 | 字号 | 行高 | 说明 |
| --- | --- | --- | --- |
| 页面标题 | `24px` - `28px` | `1.2` | 每页只出现一个主标题 |
| 区块标题 | `18px` - `20px` | `1.3` | 面板、表单分组标题 |
| 正文 / 表格 | `14px` - `16px` | `1.5` - `1.6` | 默认业务内容 |
| 辅助说明 | `13px` - `14px` | `1.5` | 描述、提示、备注 |
| 状态标签 | `12px` - `13px` | `1.2` | 标签、角标、短状态 |

### 文本规则

- 标题文案要短，说明性内容放到副标题或提示中。
- 按钮文字使用动词短语，例如“创建项目”“上传新版”“确认定稿”。
- 表格和列表中的长文本必须允许换行或省略，不能撑破容器。
- 不使用负字距，不根据视口宽度动态缩放字体。

## 间距、圆角与尺寸

### 间距

| 用途 | 建议值 |
| --- | --- |
| 页面外边距 | `28px`，移动端 `20px` |
| 页面区块间距 | `20px` - `24px` |
| 面板内部 padding | `16px` - `24px` |
| 表单项间距 | `14px` - `18px` |
| 列表项间距 | `10px` - `14px` |
| 按钮内边距 | `8px 14px` 或 `10px 16px` |

### 圆角

- 普通面板、卡片、输入框、按钮默认 `8px`。
- 品牌标记、图标按钮可使用 `8px`。
- 状态标签可使用胶囊圆角。
- 除头像、状态点和胶囊标签外，不要大面积使用超大圆角。

### 稳定尺寸

- 工具栏、按钮、状态标签、表格行高应有稳定尺寸。
- 上传区、预览区、标注画布应设置明确的最小高度或宽高比例。
- 动态内容加载后不能造成关键操作按钮位置大幅跳动。

## 组件风格

### 按钮

| 类型 | 使用场景 | 风格 |
| --- | --- | --- |
| 主按钮 | 创建项目、上传新版、确认定稿 | 青绿色背景、白色文字 |
| 次按钮 | 取消、返回、复制链接 | 白底、标准边框、主文本 |
| 危险按钮 | 作废、停用、删除草稿 | 红色文字或红色背景，谨慎使用 |
| 图标按钮 | 预览缩放、撤销、关闭、更多操作 | 使用图标，悬停显示提示 |

主按钮每个区域尽量只保留一个。危险操作必须有确认步骤。

Element Plus 使用约定：

- 主按钮使用 `type="primary"`，主题色由全局 CSS 变量覆盖为 `#2a9d8f`。
- 危险操作使用 `type="danger"`，并配合 `ElMessageBox.confirm` 二次确认。
- 工具按钮优先使用 `@element-plus/icons-vue` 图标，并通过 `title` 或 tooltip 说明含义。

### 表单

- 标签置于输入框上方或左侧，整页保持一致。
- 必填项使用清晰标识，但不要用大段提示文案淹没表单。
- 错误提示放在字段下方，使用错误状态色。
- 客户审稿页表单要短，优先收集姓名、联系方式和修改意见等必要信息。
- 表单优先使用 `ElForm`、`ElFormItem`、`ElInput`、`ElSelect`、`ElDatePicker` 等 Element Plus 组件。
- 表单校验规则应集中声明，避免在模板中散落复杂判断。

### 表格和列表

- 后台项目列表优先使用表格或密集列表。
- 表格列顺序优先展示：项目名称、客户、负责人、状态、当前版本、更新时间、操作。
- 状态字段使用统一状态标签。
- 行操作保持简短，更多操作收纳到菜单中。
- 数据表格优先使用 `ElTable` 和 `ElPagination`。
- 小屏下如果表格不可读，可切换为列表卡片，但筛选、状态和行操作语义要保持一致。

### 状态标签

项目状态建议统一映射：

| 项目状态 | 标签文案 | 颜色类型 |
| --- | --- | --- |
| `draft` | 草稿 | 中性 |
| `waiting_feedback` | 待客户反馈 | 信息 |
| `change_requested` | 需修改 | 警告 |
| `waiting_confirm` | 待确认 | 警告 |
| `confirmed` | 已确认 | 成功 |
| `archived` | 已归档 | 中性 |

标签文案要短，不在标签里写完整句子。

状态标签优先使用 `ElTag`。除 Element Plus 默认状态外，项目状态应按本文档状态色做轻量定制，确保“待反馈、需修改、待确认、已确认、已归档”可快速区分。

### 上传区

- 上传区要明确展示支持格式、大小限制和当前上传状态。
- 上传过程中显示进度和可取消状态。
- 上传失败要提供失败原因和重试入口。
- 已确认版本关联文件默认不提供删除入口。
- 上传入口优先使用 `ElUpload`，但上传流程、鉴权头、失败重试和已确认版本保护规则由业务层控制。

### 设计稿预览与标注工具

- 预览区以设计稿本身为视觉中心，工具栏保持克制。
- 标注颜色需要与设计稿内容形成对比，默认可使用青绿或蓝色描边。
- 标注点、矩形框、评论列表要能互相定位。
- 坐标和标注展示要适配不同屏幕尺寸，避免只在固定像素宽度下可用。

### 弹窗与浮层

- 弹窗只用于确认、编辑、短流程表单和关键提示。
- 弹窗标题要直接说明动作，例如“确认定稿”“上传新版”。
- 确认类弹窗按钮顺序保持一致：次按钮在左，主按钮或危险按钮在右。
- 下拉菜单、日期选择、更多操作等浮层使用轻微阴影和白底。

## 响应式规范

### 断点建议

| 宽度 | 处理方式 |
| --- | --- |
| `>= 1024px` | 标准后台布局，左侧导航 + 内容区 |
| `820px` - `1023px` | 收紧内容区，减少并排列数 |
| `< 820px` | 导航改为顶部或堆叠布局 |
| `< 520px` | 单列布局，按钮和表单适配触控 |

### 移动端要求

- 客户审稿页必须优先适配移动端。
- 后台页面至少保证可查看、可筛选、可进入详情。
- 表格在小屏下可改为列表卡片，避免横向挤压到不可读。
- 主要按钮触控高度不低于 `40px`。

## 页面类型规范

### 工作台

- 首屏展示关键状态统计和待办列表。
- 指标卡片数量控制在 3-5 个。
- 待处理事项按业务紧急程度排序：需修改、待确认、待反馈、已确认。

### 项目列表

- 筛选区应支持状态、负责人、客户关键字。
- 状态标签和更新时间要易扫描。
- 操作区只放高频动作，例如“查看”“复制链接”。

### 项目详情

- 页面核心信息包括项目状态、客户信息、当前版本、版本列表、标注列表和确认记录。
- 版本切换不应丢失当前上下文。
- 确认记录区域要突出确认版本、确认时间、确认人和访问来源。

### 客户审稿页

- 不出现后台管理导航。
- 预览区优先，标注工具和提交意见紧邻预览。
- “确认定稿”是关键动作，必须清楚表达确认的是当前版本。
- 链接失效、项目已归档、版本不存在等状态要有明确空状态。

## 禁用事项

- 不做营销型首页作为主入口。
- 不使用大面积渐变、装饰性光斑、复杂背景图。
- 不让页面被单一颜色主导，深蓝和青绿都应克制使用。
- 不在卡片中再嵌套卡片。
- 不用文字按钮替代明确图标能表达的工具操作，例如缩放、关闭、更多。
- 不让文字溢出按钮、标签、表格单元格或卡片。
- 不直接暴露 MinIO 内部地址或技术细节给客户页面。
- 不把确认记录、已确认版本等关键业务状态做成弱提示。

## 与代码实现的关系

- 全局基础样式放在 `frontend/src/assets/main.css`。
- 业务组件应优先复用全局色值、间距、圆角和状态标签规则。
- Element Plus 通过 Vite 插件按需自动导入组件和样式，主题变量在 `frontend/src/assets/main.css` 覆盖。
- 后续如继续补充项目 CSS 变量，变量名应按语义命名，例如 `--color-primary`、`--color-border`、`--radius-base`，不要按具体颜色命名。
- 新增页面前应先确认所属场景：后台管理页或客户公开审稿页，再选择对应布局和信息密度。
